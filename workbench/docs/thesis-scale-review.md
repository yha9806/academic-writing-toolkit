# 毕业论文与超长文档审阅

以下命令在仓库的 `workbench/` 目录运行；从仓库根目录安装请见[组件入口](../README.md)。

当前源码版已经加入针对 200 页以上论文的分批、分层、增量处理。发布的
v0.5.0 安装包尚不包含这些功能，请从当前仓库安装。

## 开始使用

```powershell
python -m pip install -e ".[documents]"
awt
```

打开首页的 **跨文件 / PDF / DOCX 审阅**。模型配置见
[多模型设置](setup-model-providers.md)。日常文字审阅可用旧版本或小模型；
不要求 GPT-6、大上下文、工具调用、原生异步接口或额外的向量数据库。

1. 导入整份 PDF、DOCX，或按章节保存的文件，填写本轮检查要求。
2. 检查章节划分和自动识别的类别，查看未完成批次及预计 token 预留量。
3. 选择经济档或小上下文档，设置本次愿意承担的调用总量，再开始。
4. 在章节卡片、主张—证据索引中检查结果；点定位可以打开原文和所在页面。
5. 修改论文后，先暂停，上传**同名修改文件**，查看复用和待复查范围，再继续。
6. 上传修改后的副本进行本地逐页排版对照，保存检查过的页面记录。
7. 打开 **投稿前校验（本地）**，配置学校或期刊的要求、大纲与材料清单，
   生成当前版本的统一报告。见 [投稿前校验说明](setup-submission-checks.md)。

## 长文档如何处理

| 环节 | 处理方式 |
|---|---|
| 上传 | 每次传输 1 MB，并显示进度；最多 20 份、每份 80 MB、合计 160 MB |
| 文字提取 | PDF 最多 1,000 页；合并附近同栏文字行，同时保留每行原始定位和坐标 |
| 局部审阅 | 按所选模型的输入预算分批，每批独立保存 |
| 章节审阅 | 大文档增加章节层检查，以已提取主张的原文引文作为输入 |
| 跨章节对照 | 从各章原文锚点中进行本地关键词检索，再分批核对相关部分 |
| 页面操作 | 原文、主张、发现、图像与历史记录分页；进度刷新不携带整篇论文 |
| 中断恢复 | 保存请求前预算、已完成结果和失败状态；重启后继续未完成部分 |
| 修订复查 | 复用内容、要求及配置仍匹配的完整批次；受影响章节和关联检查重算 |
| 排版对照 | 逐页渲染并保存，可暂停、取消和继续；只加载正在看的页面 |
| 投稿前校验 | 本地扫描所选文件；报告分页，标出阻断、警告、人工核对与未检查项，绑定稿件和规则版本 |

提取还受每份文件 1,200 万字符和 10 万文字区域的边界限制。1,000 页是
程序输入上限；目前完整规模验证使用的是 200 页合成 PDF。

跨章节检查目前重点覆盖摘要、方法、结果、讨论之间的五组关系；未知类别
多文件还会加入相邻文件比较。大文档每章最多取 80 个候选锚点、每类最多
160 个，按输入预算比较。界面会列出未纳入的原文；完成计划内批次不代表
全文所有潜在关系均已检查。章节摘要也不能代替引文证据。

## 成本与旧模型

| 档位 | 每批输入估算上限 | 每批输出上限 | 初始总调用上限 |
|---|---:|---:|---:|
| 小上下文 | 2,400 token | 800 token | 8 |
| 经济（默认） | 4,000 token | 1,200 token | 12 |
| 均衡 | 8,000 token | 2,200 token | 24 |

初始预算适合先试跑。200 页通常需要多轮继续或明确提高总上限；允许的
最高总量为 5,000 次调用和 2,000 万估算 token。初始计划只包括已规划的
文字批次，后续章节和关联批次也受同一总预算限制。小批次适应较小上下文，
但会增加调用次数；总费用还取决于模型单价和输出用量。

系统不会自动升级模型、切换供应商或进行付费重试。图像默认不发送；如需
模型核对图表，须先配置支持图像的模型，再明确选择页面。导入、检索、
预览、恢复和排版渲染均不调用模型。

调用次数和 token 在发送前预留，失败或结果不明的请求仍计入预算。
暂停或取消会停止后续批次；已发出的请求仍可能完成并计费。进程崩溃时
结果不明的请求须明确选择重试。本地估算并非供应商账单或保证不超支的
货币限额。

## 同名修改文件的复用规则

复用需要整批原文及顺序、审阅要求、模型配置、章节类别和结果格式均相同，
并重新校验引文定位。插入一段文字会使所在旧批次失效；不受影响的完整
批次仍可复用。章级和跨章结果还绑定完整章节内容，因此未改动的短引文
不会掩盖同章其他地方的变化。

历史结果和此前用量不会清零；相同文件哈希不会创建多余版本。中途改换
审阅要求时，旧覆盖标记为待复查。被替换文件的旧图像结果不复用；要让
模型查看新图像，当前需新建任务并重新勾选。本地预览和排版对照仍可在
原任务中进行。

## 200 页验证记录

测试材料是每页 42 行正文的虚构单栏 PDF，共 742,046 个提取字符。以下
对比只改变文字行合并方式，使用同一规划器及预算：

| 档位 | 合并前文字批次 | 合并后文字批次 | 减少 |
|---|---:|---:|---:|
| 小上下文 | 435 | 226 | 48.0% |
| 经济 | 207 | 100 | 51.7% |
| 均衡 | 92 | 44 | 52.2% |

8,600 个原始文字矩形合并为 1,000 个区域，原始定位全部保留。导入后紧凑
进度响应约 2 KB。经济档完整模拟审阅包含后续章节和关联步骤，共 151 次
模拟调用；修改第 199 页一处内容后复用 991 个区域，新增 21 次模拟调用。
实际本地排版完成全部 200 对页面，并仅检出第 199 页变化。

这些数字衡量本地处理和缓存效果，未调用任何付费模型，也不代表真实论文
的审阅质量、供应商费用或响应时间。完整数据见
[200 页机器可读结果](../final_output/thesis-scale-200-2026-09-05.json)。

复现命令（另外安装 `reportlab` 用于生成虚构 PDF）：

```powershell
python scripts/check-thesis-scale.py --pages 200 --run-fixture --layout --output final_output/thesis-scale.json
```

扫描 PDF 没有自动 OCR；复杂多栏、公式和图表仍须查看页面。DOCX 的段落、
表格位置可直接保留，稳定页码须经渲染确定。精确核对 Word 排版时，请用
Word 导出的 PDF。原文件不会被覆盖，审阅意见和页面检查记录均须由作者
判断与确认。
