# 研究规划技能：真实选题回溯对照方案

**Status: proposed; not run.** 2026-10-09。用于决定 [PR #131](https://github.com/yha9806/academic-writing-toolkit/pull/131) 中的技能是否值得进入目录。此文件提供试用步骤与判据框架，不代表案例已经选定、判据已经由研究者确认或试用已经完成。方法与范围见[功能草案](2026-10-08-research-direction-and-paper-planning.md)。

## 要回答的问题

给定同一条研究线起始时能拿到的材料，`research-plan` 能否比不装技能的同一前沿模型更早指出会改变行动的关键未知，并提出当时可执行、能区分后续路径的最小验证？记录更差、相同和无法判断的情况，不以写得完整、用了模板或预测到结局代替有用性。

回溯试用最多支持这些案例上的比较结论。它不能证明研究者当时会照做、节约了多少实际时间，也不能替代一次真实研究过程中的使用反馈。

## 运行前冻结

复制[试用记录](../../templates/research-plan-trial-record.md)到私有试用目录，先完成准备部分：

- **案例与选择理由。** 由研究者选定已有后续结论的真实研究线，列出全部纳入及排除案例和理由。覆盖不同贡献类型；未覆盖的阶段或类型写成局限。案例数量和重复次数在看输出前确定，不由工具编造。
- **材料截止点。** 每例分开保存起始材料与后续结论，记录原始日期、来源、文件清单和 SHA-256。起始材料包括当时的想法、目标和资源，不能根据后来失败的原因改写成暗示答案的提问。只有事后回忆而没有可恢复早期材料时，单列为回忆性演练。
- **参考结论。** 由熟悉该研究线的人在私有记录中写明后来实际出现的关键问题、证据定位及其当时是否可发现。它是评估参照，不是唯一正确答案；最终未发生的合理风险也可有价值。此部分对执行模型隐藏。
- **比较条件。** 固定模型标识、版本或调用日期、宿主、参数、工具、追问次数和输出预算。固定技能提交与资源哈希。记录两组共同使用的普通任务提示，不把技能的六项清单、讨论模板或预期答案塞进无技能组。
- **预定判据与决策者。** 在下表框架内为案例写明什么样的发现会改变行动、什么算当时可做的验证、如何处理分歧。维护者在运行前确认入目录所需的比较证据；判据未定时只做演练，不称为正式对照。

准备记录冻结后再运行。改动材料、技能或判据时另开版本，保留旧记录，不根据已看到的输出修改判据后重新宣布同一轮通过。

## 两组怎样运行

1. 每例两组都用独立的新会话和隔离工作区，只能读取相同的起始材料。无技能组不加载该技能、它的模板或包含其内容的项目指令、记忆、历史对话；有技能组仅多加载固定版本的技能包。记录实际暴露的指令和可用工具。只开新会话而仍自动加载全局技能，不构成无技能对照。
2. 使用相同的自然任务请求，例如“请根据所附起始材料帮我判断下一步值得调查什么，并说明需要补充的证据”。运行顺序与给评分者看的匿名编号分别随机化，并把映射保存在评分者暂时看不到的位置。
3. 首轮采用固定材料包，不实时浏览，以免检索到截止点之后的工作或事后结论。材料不足时允许指出待查事项。若另做可检索版本，另开一轮并限定可用资料的日期，两组规则相同。
4. 若允许追问，由记录保管者只按起始材料回答，保留完整问答和“未知”回复；两组追问上限相同。不能为了帮助某组而补入后续结论。模型输出、工具记录、用时、费用和失败尝试全部保存，不能挑选最好的一次。
5. 两组输出完成并固定后再交给评分者。评分者可看起始材料及参考结论，先逐例判断，再揭示分组。尽量请未参与运行的人评分；若文风或格式暴露条件，记录盲法限制。两组无法保持条件一致或发生信息泄漏时，标为无效对照，单独说明原因。

正式运行前可用明确标注的虚构小案例检查隔离、编号和保存步骤；它仅验证试用流程，不计入真实案例结果。

## 逐例判断

每项记录“有具体依据／部分成立／没有指出／无法判断”，并引用输出中的原话或位置，以及材料中的依据。另记相对另一组是更有帮助、相当、更差还是无法比较，不合成一个研究价值总分。

| 观察项 | 什么算有用 | 什么不能算通过 |
|---|---|---|
| 关键未知或硬约束 | 指向具体缺口，解释为什么会改变该案例的下一步；即使不能预知后来结果，也能提出合理检查 | 泛泛列出数据、时间、创新性，未联系本案；靠事后信息猜中结局 |
| 最小验证 | 当时可执行，说明比较对象或替代解释、资源上限及支持、不支持、不清楚时的路径 | 要求先做完整研究；依赖当时不存在的材料；没有可能改变决定的结果 |
| 更简单的已有路径 | 据给定材料识别现成方法或合理的核查任务，说明还剩什么问题 | 未检索就断言不存在已有工作，或为新方法强造需求 |
| 论文与研究主线 | 适用时分别解释学位主线与单篇贡献，保留证据依赖 | 机械一章一篇、以工作量或期刊档次充当贡献 |
| 不确定性与决定 | 区分设想、报告和结果；保留相反证据及研究者的决定权 | 伪造来源、数据权限、学位要求或结果；把工具建议记成人工认可 |
| 记录负担 | 研究者能指出新增记录是否影响下一步，记录整理、阅读和维护的实际耗时 | 只以篇幅更长、表格更多或格式齐全证明效果 |

后续更新能力另作配对轮次：两组各保留自己的初始记录，再接收相同的新证据。检查能否恢复原文件、解释判断变化和提前复看的原因；没有新增依据的未知项是否保持未知；已投入工作是否被错误当作继续理由。不要把这一轮和起始决策结果混在一起。

## 怎样形成结论

- 先列全部预定案例、全部重复及缺失/无效原因，再按观察项给出有技能较好、相当、较差、无法判断的数量。不能把无法判断当通过，也不能丢掉负面案例。
- 对每个声称的优势，指出新增了哪个会影响行动的发现或验证，以及无技能组缺少什么。评分分歧保留，最终由运行前指定的研究者判断；代码、模型或本文件不替人作决定。
- 对伪造证据、越过研究者决定或泄漏后续信息等具体失败，记录影响、原因和处理。尚未处理的实质性失败不能用其他案例的好结果抵消为通过。
- 无明确比较优势、证据不足或记录负担抵消收益时，保留方法文档与模板，继续修改、暂缓或放弃技能入目录。若发现优势，也只形成附有限制的入目录建议，仍需人工审阅。

私有起始材料、后续结论、会话原文、可识别项目名和本机路径不进入公开仓库。公开摘要可以记录协议与技能版本、匿名案例数量、比较条件、分项结果、失败类型和待决事项；具体项目摘录只在研究者明确同意公开后使用。CI 和合成演练均不代替这份真实对照结果。
